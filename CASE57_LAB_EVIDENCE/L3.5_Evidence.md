# L3.5 – Docker Compose Application/Database Communication

## Requirement

Run the duty-limit validator with a database using Docker Compose and retain evidence of the application's real database connection and result.

## Actual execution

The Compose configuration validated with `docker compose config --quiet`. The `db` service used PostgreSQL 16 Alpine; the `validator` image was built from `Dockerfile.compose`. The actual execution and follow-up are recorded in `DOCKER/compose_execution.log` and `DOCKER/compose_run_evidence.txt`.

- PostgreSQL reached its healthy state before the validator ran.
- The validator connected to PostgreSQL, ran `validate_duty(10, 60, 10)`, and reported `accepted=True`.
- The validator inserted a row in `duty_checks`; a direct `psql` query confirmed two persisted rows after the independent second run.
- Both validator one-shot containers exited with code 0. PostgreSQL remained up and healthy during the live verification capture.
- `DOCKER/compose_live_verification.png` is a genuine terminal capture of the container state, successful validator output, and direct row-count query.

The validator is deliberately a one-shot workload, so its successful container exits after writing the row. The database remains healthy. Do not describe this as a continuously running validator web service or as a Docker image built by Jenkins.
