# L2.1 – Agile Manifesto Practices

## Requirement

Write six Airline Crew Scheduling practices and map each to an Agile Manifesto value or principle.

## Case-specific practice table

| # | Practice statement for this project | Agile value/principle | Why it fits |
|---:|---|---|---|
| 1 | Demonstrate a working validator for one rule before expanding it to every constraint. | Working software over comprehensive documentation | A runnable slice gives the team concrete behavior to inspect. |
| 2 | Review the daily/rest/weekly assumptions with the authorized rule owner before treating them as law. | Customer collaboration over contract negotiation | Direct clarification is safer than interpreting ambiguous wording. |
| 3 | Reprioritize the backlog when a confirmed duty rule changes. | Responding to change over following a plan | Rule changes can affect safety-critical acceptance criteria. |
| 4 | Pair each rule change with boundary tests and review the result with stakeholders. | Continuous attention to technical excellence | Automated checks reduce regressions while review confirms intent. |
| 5 | Keep a concise, prioritized list of validator stories and revisit it each sprint. | Welcome changing requirements, even late in development | New clarifications can enter the backlog in a controlled way. |
| 6 | Keep human review accountable for AI-generated requirements and tests. | Individuals and interactions over processes and tools | AI output is assistance, not stakeholder approval. |

These are proposed team practices for the case; the existing repository does not evidence that a functioning Agile team executed ceremonies.
