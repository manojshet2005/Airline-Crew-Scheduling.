## Function before refactoring

The following is the pre-refactor `validate_duty` function as it existed in the working tree immediately before the L3.2 edit. Existing uncommitted project changes were preserved.

```python
def validate_duty(hours_today, hours_last_7_days, rest_hours):
    """
    Validate a crew member's duty hours against the assumed rules.

    R1: Daily duty must not exceed 10 hours.
    R2: Rest between duties must be at least 10 hours.
    R3: Duty in 7 days must not exceed 60 hours.
    R4: Negative values are invalid.
    """

    if hours_today < 0 or hours_last_7_days < 0 or rest_hours < 0:
        raise ValueError("Duty hours and rest hours cannot be negative.")

    if hours_today > 10:
        return False, "Daily duty limit exceeded."

    if rest_hours < 10:
        return False, "Minimum rest requirement not met."

    if hours_last_7_days > 60:
        return False, "Weekly duty limit exceeded."

    return True, "Duty schedule accepted."
```

## Function after refactoring

```python
def validate_duty(hours_today, hours_last_7_days, rest_hours):
    """
    Validate a crew member's duty hours against the assumed rules.

    R1: Daily duty must not exceed 10 hours.
    R2: Rest between duties must be at least 10 hours.
    R3: Duty in 7 days must not exceed 60 hours.
    R4: Negative values are invalid.
    """

    for hours in (hours_today, hours_last_7_days, rest_hours):
        if hours < 0:
            raise ValueError("Duty hours and rest hours cannot be negative.")

    if hours_today > 10:
        return False, "Daily duty limit exceeded."

    if rest_hours < 10:
        return False, "Minimum rest requirement not met."

    if hours_last_7_days > 60:
        return False, "Weekly duty limit exceeded."

    return True, "Duty schedule accepted."
```

## What changed and why

The three negative-input checks were consolidated into an iteration over the three input values. This avoids repeating the same comparison and exception while keeping the validation order (daily, rolling seven-day, rest) unchanged. The exception type and message, duty-rule checks, rule priority, return tuples, accepted boundaries, parameters, and return behavior were not changed.

No unrelated code or tests were edited for L3.2. No additional tests were necessary: the existing 20-test suite covers the ordinary and boundary cases, and the direct before/after comparison below checks exact return reasons, multiple-rule priority, and each negative-input position.
