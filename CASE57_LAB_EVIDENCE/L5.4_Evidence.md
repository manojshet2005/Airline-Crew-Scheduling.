## Reproducible test method and actual results

Run from the repository root:

```powershell
.\venv\Scripts\python.exe CASE57_LAB_EVIDENCE\L5.4_comparison.py
```

The script calls the project validator and the saved AI-reference function on the same ten inputs, classifies results against explicit expected outcomes, and prints two supplementary input checks.

| Test | Input | Expected | Project validator | AI reference |
|---|---|---|---|---|
| Exact boundaries | `(10,60,10)` | Accept | Pass | Pass |
| Typical valid | `(8,40,12)` | Accept | Pass | Pass |
| Daily violation | `(10.01,40,12)` | Daily rejection | Pass | Pass |
| Rest violation | `(8,40,9.99)` | Rest rejection | Pass | Pass |
| Weekly violation | `(8,60.01,12)` | Weekly rejection | Pass | Pass |
| Daily before rest | `(11,40,9)` | Daily rejection first | Pass | Pass |
| Rest before weekly | `(8,61,9)` | Rest rejection first | Pass | Pass |
| Negative input | `(-1,40,12)` | `ValueError` | Pass | Pass |
| Boolean input | `(True,40,12)` | `ValueError` | Pass | **Fail: accepted** |
| NaN input | `(NaN,40,12)` | `ValueError` | Pass | **Fail: accepted** |

Actual required-suite result: **project 10/10; AI reference 8/10**. Supplementary checks: for `"8"` the project raised `ValueError` and the AI reference raised `TypeError`; for positive infinity in the daily field the project raised `ValueError` and the AI reference returned a daily-rule rejection. These are actual behavioral mismatches, not hidden or edited out.

The complete console output, including case classifications, is in `L5.4_comparison_run.txt`. The standalone AI function is in `l54_ai_reference.py`.

## Runtime measurement

`L5.4_comparison.py` measures repeated calls to the two functions using `time.perf_counter_ns()` on the two ordinary-valid cases. It warms each function with 1,000 invocations per case, then runs seven measured rounds with 20,000 repetitions per case (40,000 calls per function per round). Measurement order alternates by round. It reports each per-call sample, range and median. The saved output records Python 3.14.7 on Windows.

Three independent executions of the seven-round procedure were captured:

| Run log | Project median ns/call (range) | AI median ns/call (range) | AI median vs project |
|---|---:|---:|---:|
| `L5.4_comparison_run.txt` | 1085.5 (936.3–1213.8) | 871.9 (846.8–1000.8) | 19.68% lower |
| `L5.4_comparison_run_02.txt` | 935.9 (922.8–1051.3) | 844.0 (813.9–870.2) | 9.81% lower |
| `L5.4_comparison_run_03.txt` | 927.2 (910.0–1133.1) | 830.6 (816.8–977.8) | 10.42% lower |

Each log preserves all seven per-call samples for both functions, sample ranges, median time per 40,000-call round, and runtime information. The direction is consistent in these three short runs, but samples and ranges vary; this is not evidence of a reliable performance advantage or a significance test. It is an in-process microbenchmark only, not a Flask endpoint, concurrency, 400-crew workload, deployment, or authoring-time measurement. The environment is Python 3.14.7 on Windows 11 Home using an AMD Ryzen 5 5500U laptop CPU.

The exact run is reproducible with the checked-in script, but timings will vary by host, runtime, load, and clock state. No comparison of original authoring time can be reconstructed from available records.

## Quality analysis and limitations

- Project validator passes the ten specified outcomes; the AI reference fails the Boolean and NaN cases and mishandles the supplementary string/infinity cases.
- The project implementation performs explicit type, Boolean, finite-number and negative-value checks. The AI reference does not; this is a correctness difference, not a legal validation of the sample 10/10/60 limits.
- Readability is qualitative: both functions are short; the project version has explicit guards and a longer reason for the input-validation contract, while the AI reference is more compact but underspecified for invalid types and non-finite numbers.
- SonarQube findings for both versions, corresponding scans, and screenshots are missing because the scanner/server/credentials/Docker engine are unavailable. Do not substitute Pylint.
- The recorded benchmark is not an authoring-time comparison or production-scale performance test.
