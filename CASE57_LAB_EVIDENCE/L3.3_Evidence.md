# L3.3 – Create and Resolve a Git Merge Conflict

## Official requirement

The official assignment book, *AI in Software Engineering Assignment Book (75 Cases)*, Case 57, printed page 230, Module 3, states:

> **L3.3 [Basic]** Create and resolve a merge conflict in duty-limit validator. Submit: conflict markers, your resolution and what AI suggested.

The official L3.3 item requests the markers, resolution, and AI suggestion. It does not specifically require screenshots for this lab. The actual command output and file contents are recorded below as text evidence. The PDF was read locally with Python `pypdf`; the original PDF was not changed or moved.

## Repository safety and setup

The original project was on branch `feature/weekly-limit` with existing modifications to `duty_validator.py` and `test_duty_validator.py`, plus untracked files. Those changes and the original branch history were preserved. To avoid touching them, the exercise used a separate temporary Git repository containing a copy of the working-tree `duty_validator.py`.

The temporary repository was initialized with local-only identity `Case 57 Lab <case57-lab@example.invalid>`. No remote was configured and nothing was pushed.

## Procedure and commands

Commands used in the temporary repository (with `<TEMP_REPO>` denoting its actual temporary directory):

```powershell
git init -b main <TEMP_REPO>
git config user.name "Case 57 Lab"
git config user.email "case57-lab@example.invalid"
Copy-Item <PROJECT>\duty_validator.py <TEMP_REPO>\duty_validator.py
git add duty_validator.py
git commit -m "Add isolated copy of duty validator for merge exercise"

git switch -c feature/l3.3-success-message
# Feature branch changes the success reason to:
# return True, "Duty schedule is within limits."
git add duty_validator.py
git commit -m "Clarify validator success message"

git switch main
# Main branch changes that same line to:
# return True, "Duty schedule accepted under sample rules."
git add duty_validator.py
git commit -m "Clarify sample-rule success message"

git merge --no-ff feature/l3.3-success-message
```

Both branches changed the same success-return line from the same base commit. Git therefore could not choose a result automatically.

## Actual conflict output

The merge command produced:

```text
Auto-merging duty_validator.py
CONFLICT (content): Merge conflict in duty_validator.py
Automatic merge failed; fix conflicts and then commit the result.
merge exit code: 1
```

`git status --short` showed the unresolved file:

```text
UU duty_validator.py
```

The combined diff showed the actual conflict markers and competing changes:

```diff
`<<<<<<< HEAD`
    return True, "Duty schedule accepted under sample rules."
`=======`
    return True, "Duty schedule is within limits."
`>>>>>>> feature/l3.3-success-message`
```

`HEAD` was `main`; the other side was `feature/l3.3-success-message`.

## AI suggestion and evaluation

The AI suggestion generated in this assistant session was:

> Replace the conflicting return strings with: `return True, "Duty schedule accepted under sample limits."` This keeps the successful bool result and conveys that these are sample rules.

This suggestion retains the accepted-schedule meaning from both alternatives and makes the sample-rule context explicit. It changes only the success message in the disposable demo copy; the function signature, boolean result, validation rules, and error behavior are unaffected by this resolution. It does not assert that the sample values are official aviation regulations.

## Resolution and verification

The conflict was resolved in the temporary copy as:

```python
    return True, "Duty schedule accepted under sample limits."
```

The resolution was staged and committed with:

```powershell
git add duty_validator.py
git commit -m "Resolve validator success-message conflict"
```

Actual merge commit:

```text
[main 80da4aa] Resolve validator success-message conflict
```

`git log --graph --oneline --decorate --all -5` showed the two divergent commits and their merge:

```text
*   80da4aa (HEAD -> main) Resolve validator success-message conflict
|\
| * ecc6bb4 (feature/l3.3-success-message) Clarify validator success message
* | 869ae3c Clarify sample-rule success message
|/
* 202dbde Add isolated copy of duty validator for merge exercise
```

`git show -s --format='commit=%H%nparents=%P%nsubject=%s' HEAD` confirmed a merge commit with two parents:

```text
commit=80da4aa75826db703f78995f6ca470a910fd1121
parents=869ae3c5b53161fd966e1f72dc5d7fbe1e49597a ecc6bb4631427a506991fb306f3d69d0deae0439
subject=Resolve validator success-message conflict
```

Further verification:

- `git status --short` returned no entries (clean working tree).
- `git diff --name-only --diff-filter=U` returned no paths (no unresolved conflicts).
- A content check found no `<<<<<<<`, `=======`, or `>>>>>>>` markers in the resolved file.
- A Python smoke check printed:

```text
(True, 'Duty schedule accepted under sample limits.')
(False, 'Daily duty limit exceeded.')
```

No pytest suite was run for this Git exercise; the temporary repository contained no copied test suite. The two smoke-check calls verified the resolved success result and an existing daily-limit rejection.
