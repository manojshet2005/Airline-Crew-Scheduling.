## One-page AI usage policy for the Case 57 team

### Purpose and permitted use

Use AI tools to draft non-sensitive requirements, test ideas, code explanations, documentation and review checklists. Treat output as a suggestion. The team owns all requirements, code, tests, release decisions and operational consequences.

### Data protection

Never submit crew names, employee identifiers, contact details, confidential rosters, credentials, production logs or non-public airline data. Use synthetic examples. Confirm the selected tool's data retention, training and privacy settings before any approved project data is submitted.

### Verification

Trace every AI-suggested duty rule to an authoritative approved source. Do not treat 10/10/60 sample limits as law. Review generated code manually, run boundary/invalid-input tests, inspect dependencies, and independently verify every AI review suggestion before accepting it. Reject outputs that invent requirements, omit edge cases, or claim tests were run when they were not.

### Human accountability and fairness

A named human reviewer must approve rule changes and releases. AI must not make unreviewed crew assignment decisions. Any future roster-generation feature must define fairness criteria, test disparate outcomes, provide an appeal path and retain accountable human oversight.

### Disclosure and records

Record tool/provider, date, purpose, prompt/output summary, accepted/changed/rejected suggestions, verification evidence and reviewer. Disclose AI use in submissions. Keep logs free of sensitive data and retain them according to course policy.

### Licensing and security

Check licenses for AI-generated snippets and every added library; comply with notices and attribution requirements. Do not paste secrets into code or prompts. Run tests and applicable security/static analysis before release.
