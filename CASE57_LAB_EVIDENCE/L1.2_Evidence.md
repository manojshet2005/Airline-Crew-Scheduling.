# L1.2 – Waterfall and Incremental Milestone Comparison

## Requirement

Plan the first duty-validator milestone using Waterfall and three Incremental deliveries; compare estimated effort, risk discovery and feedback timing.

## Planning assumptions

These are planning estimates for a small student prototype, not measured work duration or a commitment. The milestone is a validator for three configurable sample constraints; it does not include roster generation.

### Waterfall plan

| Phase | Work | Estimate |
|---|---|---:|
| Requirements | Confirm inputs, daily/rest/weekly sample limits, and outcomes | 3 hours |
| Design | Specify rule order, errors and function contract | 2 hours |
| Implementation | Implement the validator | 4 hours |
| Testing | Boundary, violation and negative-input tests | 3 hours |
| Package/review | Run suite and document limitations | 2 hours |
| **Total** | Sequential first milestone | **14 hours** |

### Incremental plan

| Increment | Deliverable | Estimate | Feedback point |
|---|---|---:|---|
| 1 | Daily limit check and daily boundary tests | 4 hours | Review daily threshold and reason |
| 2 | Minimum rest and rolling seven-day checks | 5 hours | Review all three rules and precedence |
| 3 | Negative-input handling, complete tests and packaging | 5 hours | Review test output and sample-rule caveat |
| **Total** | Three reviewable deliveries | **14 hours** | Feedback after each increment |

## Comparison

| Dimension | Waterfall | Incremental |
|---|---|---|
| Feedback timing | Primarily after the phase sequence/test milestone | After each of the three increments |
| Risk discovery | Rule misunderstandings can persist until integrated testing | Boundary/rule questions surface at each increment |
| Change cost | Later requirement changes can require rework across completed phases | A change can often be localized to a small increment |
| Weakness | Assumes requirements are stable before implementation | Requires discipline to keep increments compatible and demonstrable |
| Best fit here | Useful if authorized rules are finalized first | Preferred while the prototype and rule assumptions are being reviewed |

**Status: COMPLETE** for the planning/comparison deliverable. Estimates are explicitly estimates, not measured project records.
