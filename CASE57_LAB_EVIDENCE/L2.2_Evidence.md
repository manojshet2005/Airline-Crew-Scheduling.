# L2.2 – Sprint Goal, Definition of Done, and Acceptance Checks

## Sprint goal

By the end of the first prototype sprint, demonstrate a small Python validator that checks the three configurable sample duty limits, rejects negative values, and explains each decision.

## Definition of Done

- The validator accepts exactly the agreed inputs and documents the current sample assumptions.
- Daily, rest and rolling seven-day checks use inclusive boundaries.
- Negative inputs raise the documented `ValueError`.
- Automated tests pass for valid, boundary and violation cases.
- No claim states that the assumed limits are confirmed aviation law.

## Three executable acceptance checks

| Check | Given / When | Expected | Actual verification |
|---|---|---|---|
| Daily boundary | Given `(10, 40, 10)` | Accepted | Direct test run returned `(True, 'Duty schedule accepted.')`; PASS |
| Rest violation | Given `(8, 40, 9.99)` | Rejected with rest reason | Returned `(False, 'Minimum rest requirement not met.')`; PASS |
| Weekly violation | Given `(8, 60.01, 12)` | Rejected with weekly reason | Returned `(False, 'Weekly duty limit exceeded.')`; PASS |

The acceptance checks were executed in the L1.5 direct-case run; they are not a separate sprint-team sign-off.
